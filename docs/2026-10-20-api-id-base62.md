## TL;DR

All externally visible API identifiers (show IDs in DTOs, subtitle/package
IDs, route path segments) are currently raw `Guid` / dashed-UUID strings.
These are exposed as is — UUIDv4/v7 with hyphens and mixed casing, and —
worst of all — syntactically visible. This change establishes a **single
base62 encoding** (`0-9A-Za-z`, fixed **22 chars**) applied at the API edge:

1. **DTO JSON surface** — Guid fields serialize to base62 through an
   attribute (`[ApiId]`) wired to a custom `JsonConverter<Guid>`.
2. **Route parameters** — `{showId:guid}` constraints become `{showId:apiId}`;
   inbound validation rejects anything that is not canonical base62 (fail
   closed → 404), outbound link generation auto-encodes `Guid` route values.
3. **Composite IDs stay stable** — `sp_{id}`, `sp_{id}_ep_{N}`,
   `sp_{id}_entry_{id}` keep their `_` separators because the base62 alphabet
   is alphanumeric-only (no `_`, no `-`).
4. **Rebuildability** — decode is the exact inverse of encode; the server can
   reconstruct the original `Guid` from any identifier it emitted, strictly,
   with no ambiguity or loss.

Database schema is **unchanged** — `Guid` columns and UUIDv7 generation are
untouched; this is purely an edge-encoding concern. The UUIDv7 ordering
properties remain fully encoded (all 128 bits are carried; nothing is
truncated).

## ADR: Decision record

### Context

The API (`api.gestdown.info`) is consumed by Bazarr, SubVault, the Nuxt
frontend, and scrapers. Identifiers flow in three shapes today:

| Shape | Example | Where |
|---|---|---|
| Typed `Guid` JSON field | `"E9C1FA23-55AF-4711-8E34-3B31E2A75533"` | `ShowDto.Id` — the only typed-Guid JSON property in `AddictedProxy/Model` |
| String-interpolated ID | `"1086727A-EB71-4B24-A209-7CF22374574D"` / `sp_{uuid}_entry_{uuid}` | `SubtitleDto.SubtitleId`, `SeasonPackSubtitleDto.SubtitleId` |
| Route path segment | `{showId:guid}`, `{showUniqueId:guid}` (6 segments across TvShows/Subtitles/Media controllers) | inbound via `:guid` constraint; outbound via `Url.RouteUrl` link generation |

Problems this imposes:

- Dashed UUID strings are noisy, wrap in logs/chat, survive copy/paste poorly
  (mixed case + dashes + trailing punctuation damage), and leak internal
  representation into every consumer-facing surface.
- String-shape IDs are constructed by ad-hoc `Guid.ToString()` calls and
  parsed by ad-hoc `Guid.TryParse` — there is no single choke point, so any
  future format change would touch ~8 generate sites and ~4 parse sites.
- Outbound link generation (sitemap, download URIs) serializes `Guid` route
  values with framework defaults — the format knowledge is implicit in the
  framework, not owned by us.

### Decision

**Adopt fixed-width base62 as the canonical external encoding of every
`Guid` identifier in the API surface**, applied at the edge through three
framework funnels (JSON converter, route parameter policy, model binder),
with one `Codec` as the single source of truth for the format. The server
re-derives the original `Guid` from any emitted identifier via a strict,
canonical-only decode. No other format (dashed UUID, unpadded/short base62)
is accepted anywhere — fail closed on the entire legacy surface.

The decision covers:

1. **Format**: `Guid` (16 bytes) → positional base62 over alphabet
   `0-9A-Za-z`, rendered MSB-first, **fixed width 22 characters**
   (⌈log₆₂(2¹²⁸)⌉ = 22; value space 6₂²² ≥ 2¹²⁸). Decode accepts *only*
   exactly-22-char canonical strings from the alphabet.
2. **Where the conversion happens**: the API edge only — DTO serialization,
   route constraint/transformer, download-endpoint parser. Internally
   (services, repositories, DB) everything remains `Guid`.
3. **Tagging**: DTO properties and route parameters are tagged with an
   `[ApiId]` attribute so the convention is declared, greppable, and
   tooling-visible at each site rather than implied globally.

### Rejected alternatives (named trades)

| Alternative | Loses on | Reason |
|---|---|---|
| **base64url** (`System.Buffers.Text.Base64Url`, .NET 9+ BCL) | **DRY across the composite-ID surface** | Both `-` and `_` are inside the base64url alphabet, so every composite format (`sp_{id}_ep_{N}`, `sp_{id}_entry_{id}`) becomes ambiguous and must be re-defined with a dot separator — touching all ~8 generate sites and ~4 parse sites, plus mock-server and e2e fixtures. Zero codec code (BCL) does not compensate for re-shaping the composite surface. |
| **base32hex / Crockford** | **KISS** | 26 chars (longer), third-party alphabet conventions, no BCL support, adds care-words ("pronounceable") nobody needs. |
| **Keep dashed UUIDs** | **DRY: missing single funnel** | Status quo is precisely the N-duplicate-helpers problem the change eliminates. |
| **Slug/hash-slice encodings** (encode only part of the UUID, e.g. timestamp) | **SOLID: fail-open/lossy** | Truncating a UUIDv7 loses randomness → collision risk on rebuild; violates the round-trip invariant that makes IDs server-reconstructable. Rejected outright. |
| **Per-site manual encode/decode calls** (string params + `Codec.Call` in every action) | **DRY** | Duplicates the conversion behavior at every route/parse site; drifts. Rejected in favor of framework funnels. |

**Named trade (must appear in the PR description):** *DRY over KISS — adopted
a hand-written ~50-line base62 codec (KISS cost) to leave the entire
composite-ID generation/parse surface untouched (DRY win: the format lives
exactly once, and composite schemes never learn about the encoding).*

## Detailed design

### 1. Codec — single source of truth

**New file:** `AddictedProxy/Model/Api/Base62Id.cs`

```csharp
/// <summary>
/// Canonical external encoding of API Guid identifiers: fixed-width base62.
/// Knowledge "what an API ID looks like" lives here and nowhere else.
/// </summary>
public static class Base62Id
{
    public const int Length = 22; // ceil(log62(2^128))
    public static string Encode(Guid id) { /* … */ }
    public static bool TryDecode(ReadOnlySpan<char> value, out Guid id) { /* … */ }
    public static Guid Decode(string value) => …throws Format…;
}
```

Implementation notes:

- Built on `UInt128` (BCL, .NET 7+): `Guid.ToByteArray(bigEndian: true)`
  (plain RFC byte order — the first byte of the encoding is the first hex
  pair of the dashed form) → `UInt128` → repeated `divmod 62`; digits
  emitted MSB-first into a fixed 22-char buffer (zero-padded with the `0`
  digit), so encoding is **canonical**: one Guid ↔ one string. Because the
  mapping is plain RFC order, sorted base62 ids preserve UUIDv7 temporal
  ordering. The Go mock parses the dashed hex in the same plain order —
  the pinned cross-language vectors verify both sides byte for byte.
- Decode: strict length (`== 22`), strict alphabet lookup,
  explicit overflow bounds checks (`accumulator > UInt128.MaxValue / Radix`,
  then the addition bound) to reject values beyond 128 bits → `false`.
- Byte-order mapping (`Guid ↔ 16 bytes`) must be identical both directions;
  round-trip tests pin it against canonical vectors (all-zero Guid, max
  Guid, real UUIDv7 samples) — the vectors are the cross-language contract
  with the Go mock server.
- Pure static; no allocation beyond the output string; hot-path safe.

### 2. `[ApiId]` attribute + JSON surface

**New file:** `AddictedProxy/Model/Api/ApiIdAttribute.cs`

```csharp
/// "[ApiId]" is a pure semantic marker; the actual JSON wiring on Guid
/// properties is the literal converter attribute — the source generator
/// only resolves that literal form.
[AttributeUsage(AttributeTargets.Property | AttributeTargets.Parameter | AttributeTargets.Field)]
public sealed class ApiIdAttribute : Attribute { }

// On ShowDto.Id (annotation as built):
[Required]
[ApiId]
[JsonConverter(typeof(GuidBase62JsonConverter))]
public Guid Id { get; init; } = Id;
```

- `GuidBase62JsonConverter : JsonConverter<Guid>` — `Write` → `Encode`,
  `Read` → strict `TryDecode`, garbage → `JsonException` (MVC → 400).
- Applied at exactly one property today: `ShowDto.Id` (verified: the only
  typed `Guid` JSON property in `AddictedProxy/Model`). XML `<example>`
  values updated to 22-char base62.
- **Source-gen proof:** serialization pipeline uses
  `SerializationContext` (JSON source generation) combined with
  `DefaultJsonTypeInfoResolver`. A unit test must serialize
  `ShowDto` explicitly through `SerializationContext.Default` metadata and
  assert the base62 output — proving the property-attached converter
  survives the source-generated fast path, not just reflection mode.

### 3. Routes — `{showId:guid}` → `{showId:apiId}`

**New file:** `AddictedProxy/Controllers/ApiIdParameterPolicy.cs` (one
`IParameterPolicy` doing two jobs — validate inbound, transform outbound):

```csharp
public class ApiIdParameterPolicy : IParameterPolicy, IRouteConstraint, IOutboundParameterTransformer
```

Registered in the existing bootstrap funnel (`BootstrapController.cs`):

```csharp
options.ConstraintMap["apiId"] = typeof(ApiIdParameterPolicy);
```

- **Inbound** (`IRouteConstraint`): route matches only when the segment
  decodes strictly. Garbage → route does not match → 404, identical UX to
  the old `:guid` constraint.
- **Outbound** (`IOutboundParameterTransformer`): `Guid` route values →
  `Encode`; `string` values (already-encoded composite IDs) pass through
  unchanged. Covers sitemap URL building, `Url.RouteUrl(… new { subtitleId =
  subtitle.UniqueId })` in TvShows/Media/Subtitles controllers, and any
  future link site for free.
- **Templates**: `{showId:guid}` → `{showId:apiId}` at 6 segments
  (refresh; season subtitles; season-packs; media details; media episodes;
  subtitles/get). Route names/URLs otherwise unchanged.
- **Model binding**: the old typed binding breaks silently on base62 text
  (default `Guid` binder → 400), so a provider is added in the same
  bootstrap:

```csharp
// Scopes: modelType == typeof(Guid) && BindingSource == Path
public class ApiIdRouteModelBinderProvider : IModelBinderProvider { … }
```

  Decode → `Guid` for the `[FromRoute] Guid showId` parameter. **Controller
  and service signatures keep `Guid`** — zero churn past the binding layer.

### 4. Download endpoint (`SubtitlesController.Download`)

Single parse point — the four `Guid.TryParse` call sites become
`Base62Id.TryDecode`. Composite format logic (`sp_` prefix split, `_ep_`,
`_entry_`) is **mechanically unchanged** because the alphabet excludes `_`:

| Old token | New token (Guid half encoded, canonical vector `1086727A-EB71-4B24-A209-7CF22374574D`) |
|---|---|
| `1086727A-…` | `0VBJpBmUXk2twqNJdYbHmH` (base62, 22 chars) |
| `sp_1086727A-…` | `sp_0VBJpBmUXk2twqNJdYbHmH` |
| `sp_1086727A-…_ep_3` | `sp_0VBJpBmUXk2twqNJdYbHmH_ep_3` |
| `sp_1086727A-…_entry_<uuid2>` | `sp_0VBJpBmUXk2twqNJdYbHmH_entry_7n42DGM5Tflk9n8mt7Fhc7` (`<uuid2>` = entry Guid `ffffffff-ffff-ffff-ffff-ffffffffffff`) |

Invalid format → 400 with the existing error message (extended to mention
the expected form).

### 5. String-building sites (encode at the source)

The ID strings are *built* in DTO constructors; those sites call `Encode`:

- `SubtitleDto(Subtitle, …)` → `SubtitleId = Base62Id.Encode(subtitle.UniqueId)`
- `SubtitleDto(SeasonPackSubtitle, …, episode)` → `sp_` + encode
- `SubtitleDto(SeasonPackSubtitle, SeasonPackEntry, …)` → `sp_` + encode + `_entry_` + encode
- `SeasonPackSubtitleDto(SeasonPackSubtitle, …)` → `sp_` + encode
- `TvShowsController` / `MediaController` / `SubtitlesController` use route
  linking (`Url.RouteUrl`/`_generator.GetUriByRouteValues`). The download
  route is deliberately **not** `:apiId`-constrained (composite `sp_…`
  strings share it, so the outbound transformer does not run for it) — any
  raw-`Guid` route value there is therefore encoded **explicitly at the
  call site** (`Base62Id.Encode(subtitle.UniqueId)`), while
  already-encoded season-pack strings pass through unchanged.

### 6. What does NOT change

- Database schema, UUIDv7 generation, `UniqueId` column types
- Service layer, repositories, background jobs — `Guid` throughout
- URL shape (segments, controllers, route names) except the constraint token
- Nuxt frontend — IDs cross the boundary as opaque strings; verified not to
  pattern-match GUIDs (checked during implementation)
- Season-pack composite schemes themselves

## Consequences

**Positive**

- One canonical, URL-safe, copy-paste-safe identifier format; every ID is
  portably re-buildable server-side (round-trip invariant)
- The "what is an API ID" knowledge collapses into one codec + one attribute
- Composite pilot schemes (`sp_…`) survive untouched; future composite
  schemes can use any non-alphanumeric separator — the alphabet is
  disjoint from all of them by construction
- Outbound `Guid` route values auto-encode; inbound rejects garbage
  identically at every surface (fail closed)

**Negative / neutral**

- One hand-written codec to maintain (~50 lines, property-tested)
- **Breaking**: consumers (Bazarr, SubVault, scripts) must migrate; ever
  cached responses (`ResponseCache` 2 h–8 d) still serving dashed URLs
  return 404/400 until caches expire at swap — accepted per the
  breaking-change approval; release notes must lead with it
- Second codec implementation in the Go mock server (unavoidable; pinned by
  shared test vectors)
- Base62 strings are case-sensitive: consumers must preserve case (documented)

## Open items

- [x] ***Resolved*** Source-generated `JsonSerializerContext` + property-attached
      converters: proven in `ApiIdJsonConverterTests.Serialize_SourceGenerationMetadata_WritesBase62`.

      understands a *literal* `[JsonConverter(typeof(...))]`; a
      `JsonConverterAttribute`-*derived* attribute is ignored at generation
      time and, once both are stacked, STJ rejects the duplicate. Final

## As-built deltas

Deviations discovered during implementation; all verified by tests:

1. **`[ApiId]` is a pure marker attribute** (not a
   `JsonConverterAttribute` subclass, see open item 1) — the JSON wiring on
   `ShowDto.Id` is the literal `[JsonConverter(typeof(GuidBase62JsonConverter))]`
   placed beside the tag.
2. **`ShowDto.From(TvShow)`** replaces the second constructor (open item 4).
3. **Model binding** uses `DefaultModelBindingContext`; the binder test
   initializes `ModelState` explicitly (its default is `null`).
4. **Tooling**: `Directory.Packages.props` pins
   `Microsoft.CodeAnalysis.CSharp 5.9.0`, which requires an SDK shipping
   Roslyn ≥ 5.9 — install ≥ 10.0.4xx (e.g. via `dot.net/v1/dotnet-install.sh`)
   or the `InversionOfControl.Generator` analyzer silently fails to load
   (manifests as `CS0535` on `IBootstrap` implementations).
5. **Mock server**: fixture data keeps internal dashed UUIDs
   (`data/shows.json`); the runtime DTO layer encodes them, exactly mirroring
   the DB→API boundary in the real backend.
