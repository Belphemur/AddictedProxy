## TL;DR

Make the show catalog **machine-readable for LLMs and search engines without ever
exposing subtitle download links**. Three moves:

1. **Structured data** — schema.org JSON-LD (`TVSeries`, `TVSeason`, `TVEpisode`)
   in the SSR HTML of show pages, so crawlers and LLMs can read the full catalog
   (names, seasons, episode titles, descriptions, posters) straight from HTML.
2. **`/llms.txt`** — generated by `nuxt-ai-ready`, listing every show page from the
   existing sitemap, so agents get a curated, catalog-shaped index.
3. **Download-wall** — robots.txt gains explicit AI-crawler sections that
   `Disallow` `/subtitles/download/` for *every* agent, and the download endpoint
   emits `X-Robots-Tag: noindex, nofollow`. Metadata flows out; files do not.

## Decision record

### Context

Current discoverability surfaces (evidence):

| Surface | Where | State |
| --- | --- | --- |
| XML sitemap | `AddictedProxy/Controllers/Sitemap/SitemapController.cs` + `Services/Sitemap/MediaSitemapIndexConfiguration.cs` | ✅ lists every show as `/shows/{base62}/{slug}`, 500/page; frontend proxies `/sitemap/**` (`addicted.nuxt/server/sitemap/sitemap-proxy.ts`) |
| robots.txt | `AddictedProxy/Controllers/Sitemap/RobotsController.cs` (prod, Traefik-routed) | ⚠️ only `User-Agent: * Allow: /` + sitemap line — no AI-crawler policy, no download-path exclusion |
| robots.txt (static) | `addicted.nuxt/public/robots.txt` | ⚠️ stale duplicate hardcoded to `subvault.tv`; already replaced in prod by the backend route (commit `77ca3d41`) |
| JSON-LD structured data | `addicted.nuxt/app/**` | ❌ none anywhere; only `useSeoMeta` OG tags (`app.vue`, `app/pages/index.vue`, `app/components/media/MediaDetailView.vue`) |
| `llms.txt` | — | ❌ none |
| Download endpoint | `AddictedProxy/Controllers/Rest/SubtitlesController.cs` `Download` | ⚠️ no `X-Robots-Tag`; crawlable if a URL leaks |
| Show-page rendering | `nuxt.config.ts` `routeRules` | ⚠️ SSR-on-demand, no SWR — every crawler hit renders a full page |

**The requirement:** LLMs (and agents like Bazarr-style tooling) must be able to
*see the whole series catalog*, but must *never* be handed direct download URLs.

### Decision

1. **Adopt three Nuxt modules** — `nuxt-schema-org` (JSON-LD), `nuxt-site-config`
   (site identity), `nuxt-ai-ready` (`llms.txt`). Do **not** install the
   `@nuxtjs/seo` umbrella: its sitemap and robots modules would *duplicate
   producers the backend already owns* (see rejected alternatives).
2. **JSON-LD on show pages** (`MediaDetailView.vue`): one `TVSeries` node +
   `TVSeason` nodes for every season in `media.seasons`, + `TVEpisode` nodes for
   the episodes currently rendered (last season). **Invariant: `SubtitleDto.downloadUri`
   (and any `sp_…`/`/subtitles/download/…` value) must never appear in any
   JSON-LD node, `llms.txt` line, or sitemap entry.** Schema nodes carry name /
   seasonNumber / episodeNumber / title / description / image / url only.
   Home page gains `WebSite` + `Organization` identity nodes via `nuxt-schema-org` defaults.
3. **Site config from existing envs** — `nuxt-site-config` reads the *same*
   `APP_URL` / `APP_SITENAME` (and `NUXT_PUBLIC_*` runtime overrides) that
   `runtimeConfig.public.url` / `siteName` already use (`nuxt.config.ts`).
   One set of envs, one brand source (`useSiteBrand.ts` stays the frontend accessor).
4. **robots.txt stays backend-owned.** `RobotsController` is extended to emit:
   - `User-agent: *` + `Disallow: /subtitles/download/`
   - explicit AI-crawler groups (`GPTBot`, `OAI-SearchBot`, `ChatGPT-User`,
     `PerplexityBot`, `ClaudeBot`, `Claude-Web`, `Google-Extended`,
     `CCBot`, `Bytespider`): allowed on catalog paths (`/shows/`, `/media/`,
     `/sitemap.xml`, `/llms.txt`), same blanket `Disallow: /subtitles/download/`
   - unchanged `Sitemap:` line from `SitemapConfig.BaseUrl` (DRY — same base-URL
     source as today)
   The Nuxt static `public/robots.txt` is deleted (it is dead in prod and a
   stale, hardcoded duplicate elsewhere). `@nuxtjs/robots` is not installed.
5. **Download endpoint hardening.** `SubtitlesController.Download` sets
   `X-Robots-Tag: noindex, nofollow` on every response (including 404/429) so
   leaked URLs are never indexed regardless of robots.txt compliance.
6. **`/llms.txt` via `nuxt-ai-ready`.** The module discovers pages from the
   sitemap (which the frontend already proxies at `/sitemap.xml`) and lists
   show pages with their titles. In SSR-only mode it fetches the sitemap
   dynamically; a `{ swr: … }` route rule on `/llms.txt` keeps that cheap.
7. **SWR for show pages** — `routeRules: { '/shows/**': { swr: 3600 } }` so
   crawler hits (which render HTML server-side) are cached for an hour instead
   of re-rendering per request. Show pages also emit `Vary`-safe SSR HTML with
   JSON-LD, satisfying "AI crawlers don't execute JavaScript".

### Rejected alternatives

| Alternative | Losing principle | Reason |
| --- | --- | --- |
| Install `@nuxtjs/seo` umbrella | DRY | Its `@nuxtjs/sitemap` would become a *second* sitemap producer beside the backend's `SitemapController`, and its `@nuxtjs/robots` a second robots.txt producer beside `RobotsController`. Two copies of one behavior is exactly what DRY forbids; the backend already owns both in production (Traefik routes `robots.txt` there, commit `77ca3d41`). |
| Hand-rolled static `llms.txt` committed to `public/` | DRY | A second, manually-synced copy of the catalog index; goes stale the moment a show is added. `nuxt-ai-ready` derives it from the one source of truth (the sitemap). |
| `nuxt-llms` / Nuxt Content llms module | KISS | Designed for Nuxt Content documentation sites; this app has no Content layer. Machinery without a job. |
| Write JSON-LD by hand with `useHead` only | DRY | Loses schema-org graph linking + WebSite/WebPage defaults and re-hardcodes the site URL that `nuxt-site-config` already resolves from the shared envs. (Fallback to raw `useHead` JSON-LD is allowed only if `nuxt-schema-org` lacks a TV-type helper — see Open items.) |
| Emit episode-level download metadata in JSON-LD | SOLID | Violates the design invariant: any download-URI-shaped value in a metadata surface defeats the "no direct download access" requirement. Metadata nodes are structurally incapable of carrying one. |
| Full HTML sitemap page listing all shows | KISS | `llms.txt` + existing XML sitemap already cover machine discovery; humans have search. A third index has no remaining job. |
| Serve `X-Robots-Tag` only via middleware/filters on non-404 | SOLID | A 404/429 download response is still indexable; the header must be unconditional (fail closed). |

## Detailed design

### 1. Frontend — modules + config (`addicted.nuxt`)

New devDependencies: `nuxt-schema-org`, `nuxt-site-config`, `nuxt-ai-ready`
(exact latest versions compatible with Nuxt ^4.6.2 — resolve at install time;
`pnpm add -D <pkg>`).

`nuxt.config.ts` additions (sketch):

```ts
modules: [
  // ... existing
  "nuxt-site-config",
  "nuxt-schema-org",
  "nuxt-ai-ready",
],
site: {
  url: process.env.APP_URL ?? process.env.NUXT_PUBLIC_URL ?? "https://www.subvault.tv",
  name: process.env.APP_SITENAME ?? process.env.NUXT_PUBLIC_SITENAME ?? "Subvault",
  description: "Search and download subtitles from Addic7ed and SuperSubtitles",
  defaultLocale: "en-US",
},
schemaOrg: {
  identity: { type: "Organization", name: "Subvault" }, // resolved from site config
},
aiReady: { /* defaults; verify option names at implementation */ },
routeRules: {
  "/": { swr: 120 },
  "/shows/**": { swr: 3600 },   // NEW — crawler-render caching
  "/llms.txt": { swr: 3600 },   // NEW — dynamic sitemap fetch is cached
  // ... existing rules unchanged
},
```

Site env mapping rule (DRY): `site.url`/`site.name` use **exactly** the env
fallback chain already documented in `nuxt.config.ts` `runtimeConfig.public`
(`APP_URL`/`NUXT_PUBLIC_URL`, `APP_SITENAME`/`NUXT_PUBLIC_SITENAME`) so no new
env var is introduced and docker/Cloudflare deployments need zero changes.

### 2. Frontend — JSON-LD (`app/components/media/MediaDetailView.vue`)

After `loadViewData()` resolves `mediaInfo`:

```ts
useSchemaOrg([
  defineWebSite(),                       // from site config identity
  defineWebPage({ "@type": "WebPage" }),
  defineSchemaOrg<TVSeries>({
    "@type": "TVSeries",
    name: mediaInfo.value!.media?.name,
    alternateName: mediaInfo.value!.details?.englishName,
    description: mediaInfo.value!.details?.overview,
    image: mediaInfo.value!.details?.posterPath,
    genre: mediaInfo.value!.details?.genre ?? [],
    datePublished: mediaInfo.value!.details?.releaseYear
      ? `${mediaInfo.value!.details.releaseYear}` : undefined,
    containsSeason: (mediaInfo.value!.media?.seasons ?? []).map((n) => ({
      "@type": "TVSeason",
      seasonNumber: n,
      name: `${mediaInfo.value!.media?.name} Season ${n}`,
    })),
  }),
])
// last-season episodes (already loaded):
//   one TVEpisode node per rendered episode:
//   { "@type": "TVEpisode", episodeNumber, seasonNumber, name: title,
//     partOfSeries: { "@id" or name }, url: show-page url }
```

Exact helper names/types are verified at implementation (Open items #1). The
testable contract is the *output*, not the helper:

- SSR HTML of a show page contains `<script type="application/ld+json">`
  whose parsed content includes a `TVSeries` node with the show's name;
- **no JSON-LD node anywhere contains the substring `download` in a URI-shaped
  value** (`/subtitles/download/`, `sp_`-prefixed ids, `downloadUri` keys).

### 3. Backend — `RobotsController` (`AddictedProxy/Controllers/Sitemap/RobotsController.cs`)

Emit (exact ordering irrelevant to parsers, fixed text for testability):

```
User-Agent: *
Allow: /
Disallow: /subtitles/download/

User-Agent: GPTBot
User-Agent: OAI-SearchBot
User-Agent: ChatGPT-User
User-Agent: PerplexityBot
User-Agent: ClaudeBot
User-Agent: Claude-Web
User-Agent: Google-Extended
User-Agent: CCBot
User-Agent: Bytespider
Allow: /
Disallow: /subtitles/download/

Sitemap: {baseUrl}/sitemap.xml
# LLM agent guidance: /llms.txt lists the show catalog (metadata only).
```

The agent list lives as one `static readonly string[] AiCrawlerUserAgents` on
the controller — a single constant, tested verbatim. `BaseUrl` keeps coming
from `SitemapConfig` (unchanged injection).

### 4. Backend — download hardening (`SubtitlesController.Download`)

Before returning **any** result (success and error paths — set the header first
thing in the action):

```csharp
Response.Headers[HeaderNames.XRobotsTag] = "noindex, nofollow";
```

### 5. Frontend — stale-file removal

Delete `addicted.nuxt/public/robots.txt` (dead in prod since `77ca3d41`;
backend serves it). Keep the backend `RobotsController` as the only producer.

### 6. What does NOT change

- REST surface, DTOs, routes, IDs (base62 design untouched)
- The backend XML sitemap generator (`SitemapController`, `MediaSitemapIndexConfiguration`)
  — it already lists exactly the show pages we want discoverable
- The sitemap proxy (`server/sitemap/sitemap-proxy.ts`)
- `useSiteBrand.ts`, runtime envs, docker/Cloudflare deployment config
- Subtitle download behavior, rate limiting, caching TTLs
- Existing `useSeoMeta` calls (they compose with schema-org; OG tags stay)

## Consequences

**Positive**

- LLMs/agents can enumerate the full catalog from `llms.txt` and per-show JSON-LD
  in plain SSR HTML — no JavaScript execution needed.
- Download links are excluded at three independent layers (robots.txt groups,
  `X-Robots-Tag` header, structural absence from metadata payloads).
- Search-engine rich-result potential for TV shows; SWR cuts crawler render load.

**Negative / costs**

- Three new Nuxt dev dependencies to keep updated (renovate handles it).
- `llms.txt` is dynamic in SSR mode (fetches the proxied sitemap per cache
  window); SWR mitigates, but it is one more route with cache semantics.
- robots.txt gains a maintained agent list (`AiCrawlerUserAgents`) — new AI
  crawlers require a code change, not config.
- JSON-LD helper coverage for TV types is uncertain (Open item #1) — a raw
  schema fallback adds a second JSON-LD authoring style if needed.

**Neutral**

- `@nuxtjs/seo` umbrella not adopted; individual modules are a supported install path.
- `public/robots.txt` deletion is invisible in production (Traefik already routes
  to the backend) and only affects non-prod Nuxt-only deployments, which get the
  same file from the backend in compose stacks.

## Open items (verify during implementation)

1. **`nuxt-schema-org` TV-type helpers.** If `defineTVSeries`-style helpers don't
   exist, use the module's raw-schema escape hatch (`defineSchemaOrg` / `schema`
   node) — or, failing module integration entirely, fall back to hand-rolled
   `useHead` JSON-LD blocks while keeping `nuxt-site-config` for URL/name
   resolution. The phase-3 e2e contract (JSON-LD present, no download URIs) is
   the gate either way.
2. **`nuxt-ai-ready` package/module name and Nuxt 4.6 compat** — resolve the
   exact package (`nuxt-ai-ready`) via `npx nuxi module add` at install time.
3. **`aiReady` option names** — check the module docs at implementation; do not
   guess config keys.
4. **Traefik routing for `/llms.txt`** — production routes everything but the
   API/robots/sitemap paths to Nuxt, so `/llms.txt` should reach Nuxt by
   default; confirm on the live stack after deploy.
5. **e2e `llms.txt` reachability** — depends on the mock server: if the mock
   doesn't serve `/sitemap.xml`, phase-4's check asserts on shape (endpoint
   returns `text/plain`, non-empty) rather than catalog contents, and the
   catalog-content assertion moves to the post-deploy checklist.
